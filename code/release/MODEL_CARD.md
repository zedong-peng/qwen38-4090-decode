# Qwen3.8-27B for NInfer on one RTX 4090

[Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) re-quantized for batch-1 speculative decoding on a single
24 GB RTX 4090, in the native [NInfer](https://github.com/Neroued/ninfer) v3 `.ninfer` format, with a fine-tuned
DFlash2 drafter. It is closer to full precision than the
[NInfer release](https://huggingface.co/neroued/Qwen3.8-27B-NInfer) of the same model, and it reads 19% fewer target
weight bytes per decode round.

Write-up with interactive figures:
[zedongpeng.com/assets/html/qwen38-4090-decode.html](https://zedongpeng.com/assets/html/qwen38-4090-decode.html).
Engine patches and measurement tools: [github.com/zedong-peng/qwen38-4090-decode](https://github.com/zedong-peng/qwen38-4090-decode).

## Speed

Spec-Bench, all 480 first turns, 256 tokens, batch 1, greedy, thinking off, decode tok/s as seen by a streaming client.
One session on one RTX 4090 (450 W, PCIe Gen3), the same client for every engine:

| engine | weights | tok/s | tokens/round |
|---|---|---:|---:|
| llama.cpp a4d880f | unsloth UD-Q4_K_XL + DFlash2 Q4_K_M, up to 7 drafts | 102.2 | 4.09 |
| vLLM 0.27.1, sidnaZ single-user recipe | AutoRound W4A16 + DFlash2 W4A16, 7 drafts | 200.3 | 4.07 |
| Cinference-4090 (jram4 70ebb12) | NInfer release, 7-token chain | 177.9 | 4.03 |
| our engine | NInfer release, 16-node verify tree | 245.2 | 5.18 |
| **our engine** | **this repository**, 16-node verify tree | **322.3** | 5.43 |

Each engine runs its own public 4-bit build of the official checkpoint with a DFlash2 drafter; see the write-up for the
exact recipes. The last row is this repository.

## Quality

Against an FP32-compute reference over the BF16 checkpoint: 46,059 next-token predictions in 44 windows of 2,048
tokens, half Wikipedia prose and half CPython source, disjoint from all calibration data. KL<sub>64</sub> is
KL(reference ‖ model) on the reference's top-64 tokens.

| | KL<sub>64</sub> prose | KL<sub>64</sub> code | KL<sub>64</sub> | top-1 | PPL |
|---|---:|---:|---:|---:|---:|
| NInfer release (RTN Q4/Q5) | 0.0290 | 0.1095 | 0.0668 | 0.9250 | 3.294 |
| **this model** | **0.0265** | **0.1018** | **0.0619** | **0.9250** | **3.213** |
| BF16 checkpoint | | | | | 3.146 |

Measured with the engine and configuration below. The quality bar covers English prose and Python only; vision, MTP
and long-context behaviour were not evaluated.

## What is in the file

| Field | Value |
|---|---|
| Filename | `qwen3_8_27b.ninfer` |
| Size | 18,186,359,296 bytes (16.94 GiB) |
| SHA-256 | `37cb1507aca20b442a35f4d7833b950e0507767cf766e7140e81fad4faf43d7f` |
| Container version | 3 (1,190 objects) |
| Architecture | `Qwen3_5ForCausalLM` |

Verify a download with `sha256sum -c SHA256SUMS`. The file's provenance block records workspace-relative paths;
every tensor byte is as converted.

- **Target.** GPTQ with act-order and a per-group clip search, every text-model projection at Q4 (group 64; the
  release mixes Q4 and Q5). MLP gate/up in layers 0–31 and MLP down in layers 0–15 use codes restricted to [−4, 3], which the engine repacks into 3-bit tiles at load
  (`NINFER_Q3_SHADOW=1`). With the codes frozen, the group scales, a per-row offset and the RMSNorm gains (4.6 M
  parameters) were tuned end to end against the BF16 model's output distribution.
- **Drafter.** [z-lab/Qwen3.8-27B-DFlash2](https://huggingface.co/z-lab/Qwen3.8-27B-DFlash2) (revision `50307d4`),
  LoRA fine-tuned on 8,000 sequences generated by the quantized target, then GPTQ-quantized to Q4 (3-bit codes in
  its MLP; the release stores the drafter at Q8).
  Its 131,072-token shortlist was re-ranked with the target's own outputs.
- **As in the NInfer release recipe:** token embedding, LM head and MTP head at `q8_g32_fp16`, the vision tower at
  Q4–Q6, tokenizer and chat template.

Speculative decoding is exact: every emitted token is the target's greedy choice, so the drafter changes speed only.

## Running it

The file is a standard NInfer v3 container, but the speed and quality above need the patched engine: the
[53-patch series](https://github.com/zedong-peng/qwen38-4090-decode/tree/master/code/engine-series) on jram4's Ada
port of Cinference (base and build steps in its README; build with `-DNINFER_RDC=OFF`).

```bash
NINFER_TWO_LEVEL_HEAD=1 NINFER_HEAD_SCREEN=3 NINFER_SCREEN_TILED=1 \
NINFER_PROPOSAL_SCREEN=3 NINFER_TREE_TEMPERATURE=1.25 \
NINFER_LS8=1 NINFER_Q3_SHADOW=1 NINFER_Q3_TILED=1 NINFER_DRAFT_CONV_Q4=1 \
NINFER_KV_VI8=1 NINFER_GDN_STATE_F16=1 NINFER_GDN_CHUNKED_RECORD=1 \
NINFER_CONV_EPILOGUE=1 NINFER_ATTN_ROWSPLIT=3 \
NINFER_L2_FILL=121 NINFER_L2_FILL_NORM_KB=1536 NINFER_L2_FILL_POST_KB=768 \
NINFER_L2_FILL_GATED_KB=768 NINFER_L2_FILL_RECORD_KB=2048 NINFER_L2_FILL_ATTN_KB=4096 \
./build/apps/ninfer-serve qwen3_8_27b.ninfer --spec dflash2 --draft-tokens 15 --lm-head-draft \
  --verify-tree --kv-dtype k8v4 --max-context 32768 --kv-capacity 32768 \
  --max-concurrency 1 --prefill-chunk 1024 --temperature 0 --no-thinking
```

Limitations:
- Batch 1 and greedy decoding. The two-level LM head returns no dense logits.
- Memory: the 3-bit planes, 8-bit scale planes and LM-head screens are decode-only copies, about 4 GiB next to the Q4
  weights. The largest KV cache that starts on a 24 GB card is 57,344 tokens (65,536 does not).
- Tested on one RTX 4090 (sm_89) only.
